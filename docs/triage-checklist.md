# Incident Triage Checklist 

Use this checklist when reviewing a new security alert or high-priority ticket. 

## 1. Initial Review
- [ ] Confirm the alert/ticket source and timestamp 
- [ ] Identify the affected user, system, or asset
- [ ] Determine severify / priority (Critical, High, Medium, Low) 
- [ ] Check for related or duplicate tickets/alerts 

## 2. Gather Context 
- [ ] Review the recent activigy for the user or system 
- [ ] Check the relevant logs (authentication, endpoint, email, etc.)
- [ ] Note any unusual patterns (time, location, behavior)
- [ ] Identify business impact if known 

## 3. Evidence Collection 
- [ ]  Capture key log entries or screenshots 
- [ ] Record source IP, device name, username, and timestamps 
- [ ] Note any indicators of compromise (IOCs) if present 
- [ ] Save relevant ticket comments or user statements 

## 4. Initial Assessment 
- [ ] Is this likely a true positive, false positive, or needs more investigation? 
- [ ] Can this be resolved Tier 1 / Current level? 
- [ ] Does this require escalation? 

## 5. Documentation & Next Steps 
- [ ] Complete triage notes 
- [ ] Update the ticket with clear findings 
- [ ] Escalate if required (see Escalation Guide)
- [ ] Communicate status if needed
