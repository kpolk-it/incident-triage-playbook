# Escalation Guide 

## When to Escalate 

Escalate when any of the following apply:


- Confirmed or likely security incident (Malware, unauthorized access, data exposure)
- High or Critical severity with potential business impact
- Required access to tools beyond current permission level
- Beeds deeper investigation (forensics, threat intel, advanced log analysis)
- Multiple related alerts suggesting a broader issue
- Clear SLA or policy requirement to escalate 

## Escalation Best Practives 

- Provide a clear summary of the findings so far
- Include all relevant evidence and timestamps 
- State what has already been checked or ruled out
- Note any immediate actions already taken 
- Use the Handoff Template for consistency 

## Information to Include in Escalation

- Ticket / Alert ID
- Severity and current status 
- Affected user(s) or system(s)
- Timeline of events 
- Key evidence collected
- Actions taken so far
- Specific request for the next team
